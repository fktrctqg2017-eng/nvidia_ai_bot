# NVIDIA AI Telegram Bot

Приватный Telegram-бот для общения с AI-моделями через **NVIDIA Cloud API**
(`integrate.api.nvidia.com`, он же build.nvidia.com) и **NVIDIA NIM**
(self-hosted OpenAI-совместимые эндпоинты). Написан на **aiogram 3** (async).

## Возможности

- 👑 **Три уровня прав доступа**:
  - **0 — обычный пользователь**: доступ к диалогу с моделью только при наличии
    активной подписки (обычной, кастомной или полученной по промокоду);
  - **1 — администратор**: доступ ко всем активным моделям без лимитов, управление
    тарифами/пользователями/подписками/баном/заморозкой/рассылкой — назначается
    и снимается ВЛАДЕЛЬЦЕМ прямо в боте («👑 Админ-панель → 🛡 Управление
    администраторами»), хранится в базе данных;
  - **2 — владелец**: всё то же, что у администратора, ЭКСКЛЮЗИВНО ПЛЮС полное
    управление API-ключами и назначение/снятие администраторов; задаётся
    только статично в `config.py` (`OWNER_IDS`), через интерфейс бота не меняется.
- 💳 **Подписки/тарифы**: владелец/админ создаёт тарифы (название, цена как
  текст, лимиты запросов в минуту/час/сутки, список разрешённых моделей),
  пользователи видят их в витрине «💳 Подписки» и отправляют заявку на покупку
  (оплата происходит вручную, через контакт, указанный в админке).
- 🌟 **Кастомные (персональные) подписки** — админ/владелец может выдать
  конкретному пользователю уникальный набор моделей и лимитов, не привязанный
  ни к одному общему тарифу.
- 🎟 **Промокоды** (создание/редактирование — только у владельца):
  - выдают либо существующий тариф, либо собранную "на лету" кастомную
    подписку (свой набор моделей + лимиты);
  - настраиваемый срок действия САМОГО КОДА (когда его можно активировать) и
    отдельно — срок ВЫДАВАЕМОЙ подписки (в днях или бессрочно);
  - лимит на количество РАЗНЫХ пользователей, которые могут его активировать;
    каждый пользователь может использовать конкретный код только один раз;
  - таргетинг аудитории: для всех либо только для тех, у кого уже есть
    активная подписка;
  - администраторы и владелец сами промокоды активировать не могут — это
    инструмент для привлечения обычных пользователей;
  - пользователь вводит код через кнопку «🎁 Ввести промокод» в главном меню.
- 👤 **Профиль пользователя** («👤 Профиль» в главном меню) — показывает имя,
  ID, права, статус и тип подписки со сроком (или отметки о заморозке/бане),
  оставшуюся квоту запросов с точным временем сброса лимита, список
  доступных моделей (полными названиями) и дату регистрации (первый `/start`).
  Администраторы могут открыть профиль ЛЮБОГО пользователя из карточки в
  «👤 Пользователи и подписки».
- 🚫 **Бан и ⏸ заморозка подписки** — админ/владелец может заблокировать
  пользователя (с указанием причины — молча игнорируются его сообщения,
  на кнопки показывается предупреждение) или временно заморозить его
  подписку (срок действия ставится на паузу и точно восстанавливается при
  разморозке — ни один день/час не "сгорает").
- 🔄 **Ручной сброс лимитов запросов** — обнуляет счётчики rpm/rph/rpd
  пользователя немедленно, без ожидания окончания окна.
- 📢 **Рассылка всем пользователям** — сообщение с HTML-разметкой уходит
  каждому, кто хоть раз запускал `/start` (не только подписчикам), с
  отчётом об успешных/неуспешных доставках.
- 🔑 **Управление API-ключами** (только у владельца, «🔑 API-ключи»):
  - добавление / удаление ключей провайдеров (NVIDIA Cloud API / NVIDIA NIM);
  - включение / отключение ключей (без удаления, чтобы быстро "приостановить"
    ключ, например при исчерпании квоты);
  - просмотр списка доступных моделей у провайдера прямо из бота.
- 🤖 **Полная поддержка NVIDIA Cloud API и NVIDIA NIM** — оба провайдера работают
  через OpenAI-совместимый протокол (`openai` SDK), различается только `base_url`
  (и наличие/отсутствие обязательности API-ключа для self-hosted NIM).
- 💬 **Быстрый чат с моделью** прямо в Telegram:
  - потоковая генерация ответа (стриминг, редактирование сообщения "на лету");
  - контекст диалога (история сообщений с настраиваемой глубиной);
  - системный промпт, temperature, top_p, max_tokens — всё настраивается на лету
    через инлайн-меню, без перезапуска бота;
  - переопределение модели для конкретного пользователя;
  - несколько ключей одновременно, любой пользователь выбирает, каким пользоваться
    (из активных ключей);
  - команда `/new` или кнопка "Новый диалог" — сброс истории;
  - кнопка "Очистить историю диалога" в настройках.
- 📎 **Анализ файлов ЛЮБОГО типа, присланных напрямую в чат** (не только в
  архиве) — просто отправьте документ, и бот сам разберёт его и передаст
  модели на анализ:
  - **PDF** — постраничное извлечение текста (через `pypdf`);
  - **DOCX** — текст абзацев и таблиц (через `python-docx`);
  - **XLSX/XLSM** — содержимое всех листов как текстовые таблицы (через `openpyxl`);
  - любой другой текстовый/кодовый файл — читается напрямую, даже с
    нестандартным расширением (если это действительно текст в UTF-8);
  - результат сохраняется как "виртуальный архив" из одного файла — доступен
    агенту через инструменты `list_archive_files`/`read_archive_file` и
    пользователю через «📂 Мои файлы», как и обычные архивы.
- 🖼 **Анализ фотографий напрямую** — отправьте фото (с подписью-вопросом или
  без неё), и бот передаст его модели как мультимодальный (Vision) запрос,
  если выбранная модель поддерживает изображения.
- 🎙 **Расшифровка голосовых сообщений** — голосовое сообщение сначала
  распознаётся в текст через отдельный ключ с ролью «ASR» (настраивается в
  «⚙️ Настройки → 🎙 Ключ для голосовых»), после чего обрабатывается точно так
  же, как обычное текстовое сообщение (участвует в истории диалога и лимитах
  подписки). Поддерживает любой OpenAI-совместимый `/v1/audio/transcriptions`
  эндпоинт — self-hosted NVIDIA Speech NIM (Parakeet/Canary) или сторонний
  Whisper-совместимый сервис.
- 💭 **Управление уровнем "мышления" (reasoning/thinking)** модели — персонально
  для каждого пользователя в «⚙️ Настройки → 💭 Уровень мышления»:
  выключено / низкое / среднее / высокое. Работает с DeepSeek-R1/V3, Nemotron,
  Qwen3 и другими reasoning-моделями NVIDIA — бот одновременно передаёт параметр
  во всех форматах, которые понимают разные семейства моделей, так что не нужно
  вручную указывать "тип" модели. Для моделей без reasoning просто не имеет эффекта.
- 🗄 Все данные (профили, роли, ключи, тарифы, подписки, промокоды, настройки,
  история) хранятся в SQLite (`aiosqlite`), не нужен внешний сервер БД.
- 🧠 **Полноценный AI-агент (режим "Агент")** — включается персонально каждым
  пользователем в «⚙️ Настройки → 🤖 Режим агента» (одно сообщение в этом
  режиме расходует ровно один запрос из лимита подписки пользователя, как и
  обычное сообщение чата — см. раздел про тарифы и лимиты выше):
  - **Обработка архивов**: пришлите боту документом архив (`.zip`, `.tar`,
    `.tar.gz`/`.tgz`, `.tar.bz2`/`.tbz2`, `.tar.xz`/`.txz`, `.gz`) — он
    безопасно распакует его (защита от path traversal в любом из форматов,
    символических/жёстких ссылок и архивных бомб), картинки внутри
    конвертирует в base64 и отправит в LLM как мультимодальный (Vision) запрос
    — если выбранная модель поддерживает изображения, она их реально "увидит";
    текстовые/кодовые файлы попадают в контекст диалога как текст.
  - **📂 Просмотр файлов архива прямо в боте**: после загрузки (и в любой
    момент через главное меню «📂 Мои файлы») можно открыть архив и посмотреть
    любой файл — текстовые/кодовые файлы показываются с постраничной навигацией
    (кнопки ⬅️/➡️), изображения отправляются как настоящие фото в Telegram.
    Не нужно просить модель что-то показывать — вы можете просто открыть файл сами.
  - **Code Interpreter / песочница**: модель может сама сгенерировать Python-код
    (в блоке ` ```python ` ), бот выполнит его в изолированной песочнице и
    вернёт stdout/stderr модели, чтобы она сформировала окончательный ответ
    на основе реального результата (классический ReAct-цикл: думаю → делаю →
    смотрю результат → отвечаю или делаю ещё раз). Песочница автоматически
    выбирает самый безопасный доступный на вашей машине вариант изоляции —
    Docker, `unshare --net`, либо базовые лимиты ресурсов (для Termux и
    подобных окружений без прав на контейнеризацию), подробнее в `sandbox.py`.
  - **Agentic tool use / function calling через промпт-инжиниринг**: модель
    может запрашивать список файлов ранее загруженного архива или содержимое
    конкретного файла из него, возвращая простой JSON-объект вида
    `{"action": "read_archive_file", ...}` — бот выполняет действие и
    возвращает результат обратно в диалог с моделью. Работает с ЛЮБОЙ моделью
    NVIDIA (не требует нативной поддержки `tools=[...]` от конкретной модели).
  - **Подтверждение перед выполнением кода**: по умолчанию перед КАЖДЫМ
    запуском сгенерированного моделью кода бот показывает сам код и просит
    подтверждения кнопками «✅ Выполнить» / «❌ Отклонить» — код не запускается
    без явного согласия. Переключается персонально в «⚙️ Настройки → 🔒
    Подтверждение кода» (по умолчанию / всегда включено / всегда выключено).

## Установка

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

Самый простой способ — открыть **`config.py`** и вписать свои значения прямо
в файл (ничего дополнительно настраивать не нужно):

```python
BOT_TOKEN: str = "ВАШ_ТОКЕН_ОТ_BOTFATHER"

OWNER_IDS: list[int] = [
    111111111,   # ваш Telegram ID — владелец, максимальные права
]

ADMIN_IDS: list[int] = [
    # 222222222,  # необязательный начальный список статичных админов
]
```

- `BOT_TOKEN` — токен, полученный у [@BotFather](https://t.me/BotFather).
- `OWNER_IDS` — Telegram ID владельца(ев) бота. Единственный уровень доступа,
  который нельзя выдать/отозвать через сам интерфейс бота — только здесь, в
  коде. Владелец эксклюзивно управляет API-ключами и назначает/снимает
  администраторов; всё остальное (тарифы, подписки, промокоды, бан, заморозка,
  рассылка) доступно и админам, и владельцу.
- `ADMIN_IDS` — необязательный начальный список статичных администраторов
  (уровень 1). В отличие от владельца, администраторов можно НАЗНАЧАТЬ И
  СНИМАТЬ прямо в боте («👑 Админ-панель → 🛡 Управление администраторами»,
  доступно только владельцу) — этот список нужен только для самого первого
  запуска, можно смело оставить пустым.

Узнать свой Telegram ID можно у [@userinfobot](https://t.me/userinfobot), либо,
после первого запуска бота, командой `/id` — эта команда доступна всем.

В том же `config.py` можно поменять параметры генерации по умолчанию
(`DEFAULT_TEMPERATURE`, `DEFAULT_TOP_P`, `DEFAULT_MAX_TOKENS`, `HISTORY_LIMIT`,
`DEFAULT_REASONING_EFFORT` и т.д.), а также параметры режима агента:
- `AGENT_MAX_STEPS` — лимит шагов ReAct-цикла за одно сообщение (защита от зацикливания);
- `SANDBOX_TIMEOUT_SECONDS`, `SANDBOX_MEMORY_LIMIT_MB`, `SANDBOX_CPU_LIMIT_SECONDS` — лимиты песочницы;
- `AGENT_CONFIRM_CODE_EXECUTION_DEFAULT` — требовать ли подтверждение кода по умолчанию (`True`/`False`);
- `AGENT_CONFIRMATION_TIMEOUT_SECONDS` — сколько ждать нажатия кнопки подтверждения;
- `DEFAULT_REASONING_EFFORT` — уровень "мышления" модели по умолчанию (`off`/`low`/`medium`/`high`;
  по умолчанию `off` — не меняйте на `medium`/`high` глобально, если не увеличите заодно
  `DEFAULT_MAX_TOKENS`, иначе ответы станут медленными или пустыми, см. раздел ниже).

`AGENT_MAX_STEPS` ограничивает только количество внутренних шагов ReAct-цикла
за ОДНО сообщение (защита от зацикливания модели) — расход самого лимита
запросов подписки (`rpm`/`rph`/`rpd`) при этом ровно как за одно сообщение.

Всё подписано комментариями прямо в файле.

Запустите бота:

```bash
python main.py
```

При первом запуске файл базы данных `data/bot.db` создастся автоматически.

> 💡 Если не хотите хранить токен прямо в коде (например, чтобы не закоммитить его
> в git), можно вместо этого использовать файл `.env` (см. `.env.example`) — значения
> из `.env` имеют приоритет над значениями в `config.py`. Это не обязательно для
> обычного локального запуска (в том числе в Termux).

## Первые шаги после запуска

1. Напишите боту `/start` со своего аккаунта владельца (ID из `OWNER_IDS`).
2. Откройте **🔑 API-ключи → ➕ Добавить ключ**:
   - **Название** — любое, для вашего удобства.
   - **Провайдер** — выберите `NVIDIA Cloud API` или `NVIDIA NIM`.
   - **Base URL**:
     - для NVIDIA Cloud API по умолчанию: `https://integrate.api.nvidia.com/v1`;
     - для NVIDIA NIM — адрес вашего self-hosted контейнера, например
       `http://localhost:8000/v1` или `https://<ваш-домен>/v1`.
   - **API-ключ** — ваш ключ NVIDIA (обычно вида `nvapi-...`). Для некоторых
     self-hosted NIM-контейнеров ключ не требуется — тогда отправьте `-`.
   - **Режим модели** — на выбор:
     - ✏️ **Указать модель вручную** — одна фиксированная модель (например,
       `meta/llama-3.1-70b-instruct` для Cloud API), которую всегда использует
       этот ключ;
     - 🌐 **Разрешить все модели ключа** — модель не фиксируется заранее: при
       выборе этого ключа (в «🧠 Мои модели» либо владельцем в карточке ключа)
       бот запрашивает у провайдера АКТУАЛЬНЫЙ список реально подключённых
       моделей и предлагает выбрать любую из них кнопками — удобно, если к
       одному ключу подключено сразу несколько моделей.
   - Роль ключа по умолчанию — «💬 Чат»; сменить на «🎙 ASR» (распознавание
     голоса) или «🎨 Генерация изображений» можно в любой момент в карточке
     ключа («🎭 Изменить роль ключа»), не создавая новый ключ.
3. Откройте **👑 Админ-панель → 💳 Тарифы → ➕ Создать тариф** и создайте хотя
   бы один тариф, назначьте ему разрешённые модели (кнопка «🧠 Разрешённые
   модели» в карточке тарифа) и лимиты запросов.
   - Если в тариф включён ключ с режимом «🌐 все модели» (у которого,
     например, подключено сразу 5 моделей), рядом с ним появляется кнопка
     **«🎯/🌐 Настроить модели ключа»** — там можно точечно ограничить,
     какие ИМЕННО модели этого ключа доступны в ЭТОМ КОНКРЕТНОМ тарифе
     (например, разрешить только одну модель из пяти), не отключая сам
     ключ и не создавая для этого отдельный ключ. Если ничего не отмечено —
     доступны все модели ключа, как и раньше. Точно так же работает и для
     кастомных персональных подписок («🌟 Управлять кастомной подпиской →
     🧠 Модели → 🎯/🌐 Настроить модели ключа»).
4. Себе (владельцу) и назначенным администраторам подписка не нужна — у вас
   всегда есть доступ ко всем активным моделям без лимитов. Обычным
   пользователям подписку нужно выдать вручную («👤 Пользователи и подписки»)
   либо через промокод, либо предложить купить через витрину «💳 Подписки».
5. Просто напишите сообщение боту (или пришлите файл/фото/голосовое) —
   начнётся диалог с моделью. Для голосовых сообщений каждый пользователь
   дополнительно выбирает ASR-ключ в «⚙️ Настройки → 🎙 Ключ для голосовых».

## Управление пользователями, подписками, баном и заморозкой

Администратор или владелец открывает **👑 Админ-панель → 👤 Пользователи и
подписки → 🔍 Найти/добавить по ID** и присылает Telegram ID нужного
пользователя — откроется карточка с действиями:

- **🎁 Выдать/изменить подписку** — выбор одного из созданных тарифов и срока
  действия (в днях либо бессрочно);
- **🌟 Выдать кастомную подписку** — собрать персональный набор моделей и
  выдать на свой срок, без привязки к общему тарифу (кастомная и обычная
  подписки взаимоисключающие — выдача одной автоматически отзывает другую);
- **🗑 Забрать подписку** / **⏸ Заморозить/▶️ Разморозить подписку** —
  заморозка ставит оставшийся срок действия на паузу и точно восстанавливает
  его при разморозке;
- **🧠 Доступ к моделям (лично)** и **🚦 Личные лимиты** — точечные
  переопределения поверх тарифа для конкретного пользователя;
- **🔄 Сбросить лимиты запросов сейчас** — обнуляет счётчики немедленно;
- **🚫 Заблокировать/✅ Разблокировать пользователя** — с указанием причины;
  забаненный пользователь не получает вообще никакого ответа от бота (его
  сообщения молча игнорируются), при нажатии кнопок видит предупреждение;
- **👤 Открыть профиль** — посмотреть карточку профиля этого пользователя
  так, как её видит он сам.

Обычные пользователи **не могут** управлять API-ключами, тарифами, другими
пользователями или промокодами — им доступны только «🧠 Мои модели» (выбор
модели из тех, что разрешены их подпиской), «⚙️ Настройки», «👤 Профиль»,
«💳 Подписки» и «🎁 Ввести промокод».

## Промокоды

Раздел доступен только владельцу: **👑 Админ-панель → 🎟 Промокоды**.

1. **➕ Создать промокод** — введите название кода (например `WELCOME2026`),
   затем выберите, что он выдаёт: существующий тариф или собранную на месте
   кастомную подписку (свой набор моделей + лимиты запросов).
2. Укажите срок ВЫДАВАЕМОЙ подписки (в днях или бессрочно) и лимит на
   количество РАЗНЫХ пользователей, которые смогут его активировать (или без
   ограничения).
3. Выберите аудиторию — доступен всем, либо только тем, у кого уже есть
   активная подписка.
4. Карточка промокода (**🎟 Промокоды → выбрать код**) позволяет в любой
   момент включить/отключить его, поменять срок действия самого кода (с
   какого по какое время его можно активировать), лимит активаций, срок
   выдаваемой подписки, аудиторию, либо удалить его полностью.

Пользователь активирует код через кнопку **🎁 Ввести промокод** в главном
меню и вводит его текстом (регистр не важен). Один и тот же пользователь
может использовать конкретный код только один раз; администраторы и
владелец промокоды использовать не могут.

## Рассылка и управление администраторами

- **📢 Рассылка всем пользователям** (админ-панель) — текст с HTML-разметкой
  уходит всем, кто хоть раз запускал `/start` (независимо от наличия
  подписки), с итоговым отчётом об успешных/неуспешных доставках.
- **🛡 Управление администраторами** (только у владельца) — назначение и
  снятие администраторов (уровень 1) прямо в боте по Telegram ID, без
  перезапуска и без правки `config.py`.

В «⚙️ Настройки → 💭 Уровень мышления» доступны 4 варианта:

- 🚫 **Выключено** (по умолчанию для всех) — модель отвечает сразу, без цепочки
  рассуждений — быстрее и дешевле по токенам;
- 🌱 **Низкое** / 🌿 **Среднее** / 🌳 **Высокое** — модель "думает" перед ответом,
  тем подробнее, чем выше уровень (медленнее и больше токенов в ответе, зато
  обычно точнее на сложных задачах — математика, код, логика).

Бот одновременно передаёт этот параметр во всех распространённых форматах,
которые понимают разные семейства моделей на NVIDIA (DeepSeek-R1/V3, Qwen3,
Llama Nemotron и др.) — конкретная модель сама возьмёт то, что ей подходит,
а остальное будет проигнорировано. Ничего вручную выбирать не нужно.

> ⚠️ **Важно про max_tokens.** У reasoning-моделей "размышления" тратят токены
> из **того же лимита** `max_tokens`, что и сам финальный ответ. Если включить
> высокий уровень мышления, но оставить `max_tokens` небольшим (по умолчанию
> 1024), модель может потратить весь лимит на рассуждения и **не успеть
> написать сам ответ** — вы получите пустой ответ или предупреждение об этом
> от бота. Включайте reasoning осознанно под конкретную сложную задачу и
> одновременно увеличивайте «📏 Max tokens» в настройках (например, до
> 2048–4096). Именно поэтому по умолчанию reasoning выключен у всех —
> обычный чат остаётся быстрым, а рассуждения включаются только по желанию.

## Режим агента: как пользоваться

1. Откройте **⚙️ Настройки → 🤖 Режим агента вкл/выкл** и включите его. По
   умолчанию режим выключен (бот работает как обычный чат) — это осознанный
   выбор, чтобы выполнение кода не включалось для пользователя незаметно.
2. **Чтобы бот решал задачи с кодом**: просто попросите его текстом,
   например «посчитай сумму квадратов чисел от 1 до 100 и покажи код» — модель
   сама решит, что нужно сгенерировать и выполнить Python-код, бот прогонит
   его через песочницу и вернёт модели результат для финального ответа.
3. **Чтобы бот проанализировал архив с кодом/картинками**: пришлите боту
   архив документом — `.zip`, `.tar`, `.tar.gz`/`.tgz`, `.tar.bz2`/`.tbz2`,
   `.tar.xz`/`.txz` или `.gz` (можно с подписью — например, «найди баг в этом
   коде» или «опиши, что на скриншотах»). Бот распакует архив, покажет краткую
   сводку и сразу отправит содержимое модели на анализ.
4. **Чтобы посмотреть файлы архива самому** (без вопросов к модели) — откройте
   главное меню **📂 Мои файлы**, выберите архив и любой файл в нём. Текстовые
   файлы показываются постранично прямо в чате, картинки отправляются как фото.
   Это же меню появляется сразу после загрузки архива под сообщением с ответом.
5. Каждый архив живёт до перезапуска бота (или пока вы не удалите его вручную
   через 🗑 в файловом браузере) — во время работы с ним модель может обращаться
   к любому его файлу через инструменты `list_archive_files` / `read_archive_file`,
   даже если он не был показан ей в первом сообщении целиком (это экономит
   контекст на больших проектах).
6. **Подтверждение кода**: если оно включено (по умолчанию — да), при каждой
   попытке модели выполнить код бот пришлёт сам код и две кнопки. Пока вы не
   нажмёте одну из них (или не истечёт таймаут — по умолчанию 5 минут, код
   НЕ будет выполнен), агент "ждёт" вашего решения, не блокируя при этом
   остальную работу бота. Если код отклонён — модель получает уведомление об
   этом и может предложить альтернативу вместо кода.

> ⚠️ Код выполняется в песочнице (см. раздел «Безопасность выполнения кода»
> ниже), но, как и с любым Code Interpreter, не стоит без разбора запускать
> код от моделей на боевых/продовых машинах — используйте отдельный
> сервер/контейнер для бота, если это возможно. Подтверждение кода —
> дополнительный уровень защиты, а не замена изоляции песочницы.

## Безопасность выполнения кода (sandbox)

Модуль `sandbox.py` автоматически определяет самый безопасный доступный на
вашей машине способ изоляции и использует его без какой-либо настройки:

| Уровень | Условие активации | Что даёт |
|---|---|---|
| 🐳 Docker | Установлен `docker`, демон запущен | `--network none`, `--read-only` ФС, без root, лимиты CPU/RAM/PID |
| 🔒 `unshare --net` | Доступен бинарник `unshare`, ядро разрешает непривилегированные network namespaces | Код не имеет доступа к сети + лимиты CPU/RAM через `resource.setrlimit` |
| ⚠️ subprocess + rlimits | Работает всегда (в т.ч. Termux/Android) | Лимиты CPU-времени, памяти, числа процессов, размера файлов, wall-clock таймаут. Сеть технически не блокируется — компенсируется явным запретом в системном промпте модели писать сетевой код |

Во всех случаях код выполняется в одноразовой временной директории без
доступа к остальным файлам бота, и гарантированно убивается по истечении
таймаута (по умолчанию 15 секунд, настраивается в `config.py` →
`SANDBOX_TIMEOUT_SECONDS`, `SANDBOX_MEMORY_LIMIT_MB`, `SANDBOX_CPU_LIMIT_SECONDS`).

Дополнительный уровень защиты — **подтверждение перед выполнением** (см. выше):
даже в самом слабом режиме изоляции (Termux) код не запустится без явного
согласия пользователя, если подтверждение включено (по умолчанию — да).

### Безопасность распаковки архивов

`file_handler.py` защищает от типичных атак через архивы одинаково для всех
поддерживаемых форматов:
- **Path traversal** (`../../etc/passwd`, абсолютные пути) — путь каждого
  файла проверяется на выход за пределы временной директории распаковки.
- **Символические/жёсткие ссылки в tar-архивах** — распаковка полностью
  отклоняется, если архив их содержит (в zip-формате ссылок как таковых нет).
- **Архивные бомбы** — лимиты на суммарный распакованный размер (100 MB),
  количество файлов (200), размер одного файла (20 MB) и подозрительно
  высокую степень сжатия отдельных файлов.

Все лимиты настраиваются в начале `file_handler.py` (константы
`MAX_TOTAL_UNCOMPRESSED_BYTES`, `MAX_FILES_IN_ARCHIVE` и т.д.).

## Важные замечания по безопасности

- Никогда не публикуйте `.env` и `data/bot.db` — там хранятся API-ключи в открытом
  виде (для упрощения работы бота). Добавьте их в `.gitignore`.
- Сообщение с введённым API-ключом бот сразу удаляет из чата после обработки,
  чтобы ключ не оставался в истории переписки в Telegram.
- Система ролей и подписок полностью защищают бота от использования
  посторонними — роль и доступ проверяются в middleware на каждое сообщение
  и каждый callback; забаненные пользователи не получают вообще никакого
  ответа от бота.
- Весь "сырой" текст (ответы модели, содержимое файлов, показываемый код,
  пользовательский ввод, вставляемый в текст сообщений) экранируется от
  HTML-спецсимволов перед отправкой (`text_utils.escape_html`), чтобы `<`,
  `>`, `&` не ломали разметку сообщений в Telegram (бот работает с
  `ParseMode.HTML` глобально).

## Запуск в фоне (пример systemd)

```ini
[Unit]
Description=NVIDIA AI Telegram Bot
After=network.target

[Service]
Type=simple
WorkingDirectory=/path/to/nvidia_ai_bot
ExecStart=/path/to/nvidia_ai_bot/venv/bin/python main.py
Restart=on-failure
EnvironmentFile=/path/to/nvidia_ai_bot/.env

[Install]
WantedBy=multi-user.target
```
